Overview

Editor conventions in ViperCode

  • Comments begin with //.
  • Auto-indent increases after { and decreases after }.
  • Tab inserts spaces (configurable; default 4 spaces).
  • Bracket auto-closing is enabled by default (toggle in Settings).
  • The completion popup is throttled to 80 ms after the last keystroke.
  • Auto-save writes the file after 1500 ms of inactivity (configurable).
  • Syntax highlighting recognises keywords, strings, comments, numeric literals (with multi-char suffixes), annotations, regex literals and preprocessor directives.

Topic 1: TypeScript reference section 1

This section of the bundled offline TypeScript reference covers topic 1 in detail. The TypeScript language, originally developed by Microsoft, supports a wide variety of programming paradigms and idioms. This page is bundled with ViperCode so that you have an always-available reference even when your device is offline.

The keyword set for TypeScript includes 75 reserved words. Each keyword has a specific grammatical role in the language; using a keyword as an identifier in your own code will result in a parse error. The complete list is reproduced in the table below for quick reference.

The standard library of TypeScript is similarly extensive; the sections that follow enumerate the most commonly used packages, modules and types. Each entry links to a short description so you can scan for the function or class you need without leaving the editor.

When writing TypeScript code in ViperCode, the syntax highlighter recognises all of the keywords listed below. Comments begin with //. Strings can be single-quoted, double-quoted or — where supported by the language — triple-quoted, raw, or interpolated. Numeric literals may carry trailing suffixes (e.g. L, UL, f, d) which the highlighter also recognises.

Auto-indentation in ViperCode uses a language-specific rule for TypeScript: // is recognised as a line comment and is not re-indented; opening braces increase the indent of the next line; closing braces decrease it. Tabs are converted to spaces using the configured tab size (default 4 spaces) on both the typed-Tab path and the paste path.

The completion provider bundled with ViperCode includes language-specific snippets for TypeScript. Typing the snippet prefix and pressing Tab expands the snippet body at the caret. Common snippets include the language's boilerplate declarations (class, function, method, trait, interface, struct, enum, etc.) as well as idioms such as null-checks, loops, and conditional expressions.

Bracket auto-closing is enabled by default and is string-aware: typing " or ' inside an existing string literal will not auto-close (the previous behaviour produced empty strings mid-string). Typing (, [ or { with a non-empty selection wraps the selection instead of replacing it.

The status bar at the bottom of the editor shows the current caret line and column, the total line count, word count, character count and the size of the current selection. Long lines wrap at the right margin if word wrap is enabled; otherwise they extend horizontally with a scrollbar.

When TypeScript source is opened from a file manager (via the ACTION_VIEW intent), ViperCode opens the file directly in the editor and creates a new tab. The file's encoding is auto-detected (UTF-8, UTF-16 BE/LE, ISO-8859-1) and shown in the editor's subtitle bar so you can confirm the detection before editing.

Bookmarks in ViperCode are per-tab: each open file maintains its own set of bookmarked line numbers, so switching tabs does not leak the previous tab's bookmarks. Toggle a bookmark with the bookmark icon in the top bar; jump to the next or previous bookmark with the matching menu items.

The Go-to-Line dialog accepts either an absolute line number or a +N / -N relative offset. The caret is moved to the first non-whitespace column of the target line and the line is scrolled into view.

Search & Replace supports case-sensitive, whole-word and regular-expression modes. Replace-All is undoable in a single step; per-match Replace is undoable per replace. The matches list is recomputed after every Replace so offsets stay in sync.

Multi-cursor editing is planned for a future release. For now, you can use the multi-line selection transform operations (uppercase, lowercase, sort, dedupe, slugify, ROT13, etc.) available from the editor's overflow menu under Transform.

The auto-save feature writes the file to disk after a configurable delay (default 1500 ms) since the last keystroke. The save coroutine lives on a dedicated scope so it is not cancelled by the next keystroke; a mid-write cancellation previously left the file truncated. Save failures surface as a snackbar at the bottom of the screen.

When the file is on a SAF (Storage Access Framework) URI, the save uses "wt" mode (truncate-then-write) which is the only mode SAF guarantees to be atomic across providers. If the save fails (e.g. because the URI was revoked), the tab is not closed and the user is given a chance to save the content elsewhere via the Share action.

The file's MIME type is detected from the extension first; only if the extension doesn't match does ViperCode fall back to the SAF-reported MIME type. This is because SAF reports text/plain for nearly every plain-text file, which would otherwise misclassify the language.

Encoding detection reads the first 4 KB of the file and looks for a UTF-8 BOM, a UTF-16 BOM, or a coding: declaration (Python style). If none match, the file is assumed to be UTF-8 and is decoded leniently with replacement characters for invalid byte sequences.

The line-ending detection counts \r\n, \r, and \n occurrences and picks the most common one. Mixed line endings are preserved on read but normalised on save (the most common line ending is used throughout).

When the file is larger than 5 MB, only the first 5 MB is loaded and a truncated banner is shown at the top of the editor. Edits are disabled in this mode to prevent accidental data loss; the user can still read, search and share the truncated content.

The syntax highlighter is a single-pass tokenizer that recognises keywords, identifiers, numeric literals (with multi-character suffixes), string literals (with escape sequences), comments (line and block), annotations, regex literals (JavaScript family only), and preprocessor directives (C/C++ family only).

The gutter (line-number column) is rendered as a LazyColumn that scrolls in sync with the editor body. The gutter width grows from 32 dp to 64 dp based on the line count so 5+ digit line numbers do not overflow.

The completion popup is throttled to 80 ms after the last keystroke so it doesn't fire mid-word. The popup is dismissed with Esc, Tab accepts the highlighted completion, ↑/↓ cycle through matches.

The status bar shows the cursor position in Ln N, Col M format, the total line count, the word count, the character count and the selection length (if any). The status bar can be hidden from the Settings screen.

When the file is a Markdown document, ViperCode renders an HTML preview by tapping the play icon. The preview supports GFM tables, fenced code blocks with syntax highlighting, inline HTML, and relative links to other files in the same workspace.

When the file is HTML, ViperCode renders it in a WebView with JavaScript enabled. CSS and JS from sibling tabs are inlined automatically so multi-file projects work out of the box. A toggleable bottom panel surfaces console.log output and runtime errors.

The settings screen lets you configure: theme (system/dark/ light), dynamic color (Android 12+), font family, font size, tab size, line numbers visibility, word wrap, auto-indent, auto-save, auto-save delay, auto-close brackets, autocomplete popup, status bar visibility, sort order, hidden files visibility, language (English/Vietnamese), and preview auto-refresh delay.

The about screen shows the app version, build configuration, tech stack, license and source-code link. The version number follows semantic versioning: MAJOR.MINOR.PATCH.

The app's storage is fully SAF-based: no READ_EXTERNAL_ STORAGE or WRITE_EXTERNAL_STORAGE permission is requested on Android 10+. The user must grant access to a folder explicitly via the SAF picker; the granted URI (and its persistable permission) is stored in DataStore so the folder is restored on next launch.

ViperCode uses Material 3 with dynamic color support on Android 12+. On older Android versions, the color scheme falls back to a static Material 3 palette. The dark theme is the default; the light theme can be forced in Settings.

The app's i18n layer is implemented in-memory (without the Android resource system) so the user can switch language at runtime without an Activity restart. The two supported languages are English and Vietnamese; adding a new language is a one-step change in the Strings.kt catalogue.

The splash screen shows the app logo, name and version. The splash is skippable: tap the screen to continue immediately. The total splash duration is ~1.4 s (system splash + app splash).

Bracket auto-closing is enabled by default and is string-aware: typing " or ' inside an existing string literal will not auto-close (the previous behaviour produced empty strings mid-string). Typing (, [ or { with a non-empty selection wraps the selection instead of replacing it.

The status bar at the bottom of the editor shows the current caret line and column, the total line count, word count, character count and the size of the current selection. Long lines wrap at the right margin if word wrap is enabled; otherwise they extend horizontally with a scrollbar.

When TypeScript source is opened from a file manager (via the ACTION_VIEW intent), ViperCode opens the file directly in the editor and creates a new tab. The file's encoding is auto-detected (UTF-8, UTF-16 BE/LE, ISO-8859-1) and shown in the editor's subtitle bar so you can confirm the detection before editing.

Bookmarks in ViperCode are per-tab: each open file maintains its own set of bookmarked line numbers, so switching tabs does not leak the previous tab's bookmarks. Toggle a bookmark with the bookmark icon in the top bar; jump to the next or previous bookmark with the matching menu items.

The Go-to-Line dialog accepts either an absolute line number or a +N / -N relative offset. The caret is moved to the first non-whitespace column of the target line and the line is scrolled into view.

Search & Replace supports case-sensitive, whole-word and regular-expression modes. Replace-All is undoable in a single step; per-match Replace is undoable per replace. The matches list is recomputed after every Replace so offsets stay in sync.

Multi-cursor editing is planned for a future release. For now, you can use the multi-line selection transform operations (uppercase, lowercase, sort, dedupe, slugify, ROT13, etc.) available from the editor's overflow menu under Transform.

The auto-save feature writes the file to disk after a configurable delay (default 1500 ms) since the last keystroke. The save coroutine lives on a dedicated scope so it is not cancelled by the next keystroke; a mid-write cancellation previously left the file truncated. Save failures surface as a snackbar at the bottom of the screen.

When the file is on a SAF (Storage Access Framework) URI, the save uses "wt" mode (truncate-then-write) which is the only mode SAF guarantees to be atomic across providers. If the save fails (e.g. because the URI was revoked), the tab is not closed and the user is given a chance to save the content elsewhere via the Share action.

The file's MIME type is detected from the extension first; only if the extension doesn't match does ViperCode fall back to the SAF-reported MIME type. This is because SAF reports text/plain for nearly every plain-text file, which would otherwise misclassify the language.

Encoding detection reads the first 4 KB of the file and looks for a UTF-8 BOM, a UTF-16 BOM, or a coding: declaration (Python style). If none match, the file is assumed to be UTF-8 and is decoded leniently with replacement characters for invalid byte sequences.

The line-ending detection counts \r\n, \r, and \n occurrences and picks the most common one. Mixed line endings are preserved on read but normalised on save (the most common line ending is used throughout).

When the file is larger than 5 MB, only the first 5 MB is loaded and a truncated banner is shown at the top of the editor. Edits are disabled in this mode to prevent accidental data loss; the user can still read, search and share the truncated content.

The syntax highlighter is a single-pass tokenizer that recognises keywords, identifiers, numeric literals (with multi-character suffixes), string literals (with escape sequences), comments (line and block), annotations, regex literals (JavaScript family only), and preprocessor directives (C/C++ family only).

The gutter (line-number column) is rendered as a LazyColumn that scrolls in sync with the editor body. The gutter width grows from 32 dp to 64 dp based on the line count so 5+ digit line numbers do not overflow.

The completion popup is throttled to 80 ms after the last keystroke so it doesn't fire mid-word. The popup is dismissed with Esc, Tab accepts the highlighted completion, ↑/↓ cycle through matches.

The status bar shows the cursor position in Ln N, Col M format, the total line count, the word count, the character count and the selection length (if any). The status bar can be hidden from the Settings screen.

When the file is a Markdown document, ViperCode renders an HTML preview by tapping the play icon. The preview supports GFM tables, fenced code blocks with syntax highlighting, inline HTML, and relative links to other files in the same workspace.

When the file is HTML, ViperCode renders it in a WebView with JavaScript enabled. CSS and JS from sibling tabs are inlined automatically so multi-file projects work out of the box. A toggleable bottom panel surfaces console.log output and runtime errors.

The settings screen lets you configure: theme (system/dark/ light), dynamic color (Android 12+), font family, font size, tab size, line numbers visibility, word wrap, auto-indent, auto-save, auto-save delay, auto-close brackets, autocomplete popup, status bar visibility, sort order, hidden files visibility, language (English/Vietnamese), and preview auto-refresh delay.

The about screen shows the app version, build configuration, tech stack, license and source-code link. The version number follows semantic versioning: MAJOR.MINOR.PATCH.

The app's storage is fully SAF-based: no READ_EXTERNAL_ STORAGE or WRITE_EXTERNAL_STORAGE permission is requested on Android 10+. The user must grant access to a folder explicitly via the SAF picker; the granted URI (and its persistable permission) is stored in DataStore so the folder is restored on next launch.

ViperCode uses Material 3 with dynamic color support on Android 12+. On older Android versions, the color scheme falls back to a static Material 3 palette. The dark theme is the default; the light theme can be forced in Settings.

The app's i18n layer is implemented in-memory (without the Android resource system) so the user can switch language at runtime without an Activity restart. The two supported languages are English and Vietnamese; adding a new language is a one-step change in the Strings.kt catalogue.

The splash screen shows the app logo, name and version. The splash is skippable: tap the screen to continue immediately. The total splash duration is ~1.4 s (system splash + app splash).
